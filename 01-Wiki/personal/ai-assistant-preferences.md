# AI Assistant Preferences

**Summary:** A short list of standing preferences and facts to give an AI assistant so it stops making the same mistakes. It covers wanting requests clarified before work starts, the no-emoji rule for client websites, SEO keywords in review replies, needing programming explained from zero, and sticky call-to-action buttons on every website build.

## Key Points
- **Clarify before starting** anything that creates or changes something — no waiting for results that turn out wrong.
- Building websites for local businesses. **No emoji in any of them.**
- Review replies should carry **as many SEO keywords as possible** — "karaoke near me", "Queens karaoke", etc.
- **Assume zero programming knowledge.** Define every term, name every thing, never skip steps.
- Every website build gets **automatic sticky call-to-action buttons**.

## The Preferences As Written
1. **(Preference)** Every single prompt that creates or changes something should be clarified before being started. I do not want to wait for results that are going to end up incorrect.
2. **(Fact)** Currently starting a business creating websites for local businesses. Does **NOT WANT emoji** in any of them. I would also like all review replies to have as many SEO keywords as possible — karaoke near me, Queens karaoke, etc.
3. **(Fact)** Knows nothing about code or commands or any computer terms, or where to look for anything. I need all programmer-related help in extreme step-by-step detail, with definitions of words and names of things.
4. **(Preference)** Every single website build should have automatic call-to-action sticky buttons.

## Related Standing Instruction
A longer version of the same idea appears in the prompt templates: prioritize production-ready solutions, optimize for conversions and usability, reduce friction, critique weaknesses rather than agreeing, and give the answer as *(1) best approach, (2) exact step-by-step instructions, (3) mistakes to avoid, (4) a final copy/paste version, (5) a checklist, (6) the next best action.*

That six-part output format is worth reusing — it front-loads the reasoning and ends with something you can actually do.
